Pipeline Methodology

This page documents the analytical decisions and thresholds that affect all three layers of the CIDA pipeline: data acquisition, dimensionality reduction, and interest overlay.

Data Sources

The pipeline ingests data from four sources:

  • GovTrack — Vote JSON endpoints for House and Senate (Step 1)
  • FEC — Schedule A receipts and committee master files from bulk download (Step 7)
  • DW-NOMINATE — HS118_members.csv from voteview.com for external validation (Step 11)
  • CRS Policy Areas — vote_crs table in SQLite for CRS category analysis (Step 11)

Vote Filtering

Not all votes are analytically useful. Step 2 applies a category filter to exclude procedural, leadership, and election-related votes that do not reflect substantive legislative positions.

Chamber Total Votes Excluded Excluded % Retained
House 1,241 444 35.8% 797
Senate 691 93 13.5% 598
Excluded categories: quorum, procedural, leadership, election
Included categories: passage, passage-suspension, amendment, cloture, nomination (Senate only), veto-override

Vote Encoding

Legislator positions are encoded numerically:

  • +1 = Yea
  • −1 = Nay
  • 0 = Not voting / Present / Absent

Participation Threshold

Legislators present for fewer than 50% of filtered votes are excluded. This threshold is applied independently to each chamber and the resulting legislator list is documented.

Senate: 15 legislators excluded. Of these, 13 had 0% coverage (sworn in January 2025, after 118th Congress ended); 2 mid-term replacements with low coverage (Schiff 1.8%, Kim 3.5%)
House: No legislators excluded. All met or exceeded the 50% participation threshold.
Justification: Lowering the threshold would add no analytically useful legislators and would increase noise in the PCA solution.

PCA Configuration

Step 4 applies Principal Component Analysis to the legislator × vote matrices, with the number of components selected by parallel analysis.

Component Selection

Parallel analysis (permutation test, 200 iterations) determines the number of principal components to retain:

  • House: 4 components retained
  • Senate: 3 components retained

Sanity Checks

PC0 (first principal component) is expected to align with party affiliation, as party is the dominant explanatory factor in Congressional voting. We verify that PC0 r² with party falls within the expected range of 0.70–0.95:

FEC Acquisition

Step 7 acquires Schedule B disbursement data and committee master files from the Federal Election Commission bulk download directory (no API key required, no rate limiting).

Data Files

  • pas2{22,24}.zip (Schedule A receipts)
  • cm{22,24}.zip (committee master)
  • Source: fec.gov/files/bulk-downloads/ for 2022 and 2024 election cycles

Industry Classification

Industry classification is drawn from the ORG_TP field in the committee master file (primary), with CMTE_TP as fallback. Dollar amounts are log-transformed (log1p) before correlation with PCA scores.

Legislator Match Rate
99.3%

SSA Geometry (Step 6)

Non-metric multidimensional scaling (MDS) is applied to the legislator-to-legislator distances in the subspace of PC1 and higher (excluding PC0/party). This produces a 2D or 3D geometric layout that preserves ordering relationships.

MDS Input: Euclidean distances in PCA space (PC1+)
Target Stress: < 0.20 in 2D or 3D solution

Clustering (Step 9)

Step 9 applies hierarchical density-based clustering to identify groups of legislators with similar non-party voting patterns.

Algorithm Selection

HDBSCAN is applied first with min_cluster_size = max(5, n//20). If HDBSCAN produces fewer than 2 clusters, K-Means is used as a fallback with k=3.

External Validation

Dimensionality reduction results are validated against two independent sources:

DW-NOMINATE

Pearson correlation is computed between each principal component and the first two dimensions of the DW-NOMINATE score (HS118_members.csv from voteview.com). High correlation with PC0 and low correlation of PC1+ with NOMINATE dimensions would suggest that non-party components capture genuine, independent structure.

CRS Policy Areas

For each legislator and each CRS policy area category, we compute the mean position in that category. Pearson correlation is then computed between each PCA component and the per-legislator mean position in each policy area. This approach links voting dimensions to substantive policy concerns.

Key Thresholds

The pipeline enforces strict success conditions at each step. A step fails with a non-zero exit code if any threshold is not met.

Check Threshold House Senate Pass?
Filtered votes ≥ 300 797 598 ✓ Yes
PC0 r² with party 0.70 – 0.95 0.968 0.930 ✓ Yes
FEC legislator match rate ≥ 80% 99.3% 99.3% ✓ Yes
Clustering silhouette score > 0.30 0.765 0.737 ✓ Yes
Note on PC0 r²: The observed values (0.968 and 0.930) exceed the upper bound of the expected range (0.95). This indicates exceptionally strong alignment with party, which is not unexpected for the 118th Congress and does not affect the validity of PC1+ as non-party dimensions.

Pipeline Notes

  • Each step is a standalone Python script. Steps are run sequentially; Step 5 (interpretation) is never automated.
  • Each step writes a status JSON file (e.g., step_01_status.json) before exit.
  • Failure is strict: if any success condition is not met, the step prints the observed value, names the violated condition, and exits with code 1.
  • No live API calls occur after Step 1 (GovTrack) or Step 7 (FEC). All subsequent steps read only from SQLite.
  • The methodology log (output/methodology_log.md) is a required output that documents every exclusion count, threshold choice, and interpretation judgment.
