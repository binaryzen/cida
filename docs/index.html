CIDA

Latent dimension discovery, applied to two different kinds of data.

CIDA started as an analysis of how members of Congress vote — looking for patterns in roll-call data that don't line up with party. The same approach (reduce a large set of individual decisions to a small number of underlying axes, then check what those axes correlate with) turned out to work on a second, unrelated dataset: a decade of public bug reports for a Git client. Same acronym, different subject: Congressional Interest Dimension Analysis in iteration 1, Customer Issue Dimension Analysis in iteration 2.

Both iterations are self-contained. Neither depends on the other's data or conclusions.

Iterations

Iteration 1

Congressional Interest Dimension Analysis

PCA over 118th Congress roll-call votes (354 House, 85 Senate), checked against DW-NOMINATE and FEC contribution data. Finds a House voting dimension independent of party and of both existing NOMINATE axes.

 Iteration 2

Customer Issue Dimension Analysis

NMF and PCA over 1,000 public Sourcetree for Windows bug tickets (2013–2023). Finds that half the backlog was never triaged and that resolution depends on team decisions, not ticket content.
